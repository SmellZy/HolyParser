## 1. Implemented scope

D1 implements the accepted D-079 through D-088 token foundation and nothing
beyond that boundary:

- ordered, data-only canonical JSON sources and a closed schema;
- bounded Node 24 validation, alias resolution and deterministic generation;
- committed CSS, TypeScript metadata and SHA-256 manifest artifacts;
- authored DARK and LIGHT maps, with DARK as `:root` and SYSTEM retained only
  as preference metadata;
- approved typography, foundation scales, financial/status/data-quality/
  capability presentation, chart and forced-colour contracts;
- legal contrast-pair validation, raw-value governance, version and
  compatibility checks;
- the bounded Phase 1 bridge in `apps/web/src/app/globals.css`;
- implementation-produced tests, fixtures, rollback and D-088 visual evidence.

No component, page, DOM, copy, route, navigation, breakpoint, `layout.tsx`,
font package, dependency, lockfile, infrastructure, adapter or accepted Phase
2B document was changed.

## 2. Canonical source and schema

`src/token-set.meta.json` is the sole metadata authority. The initial
`schemaVersion`, `tokenSetVersion` and `generatorContractVersion` are all
`1.0.0`. The canonical set contains 141 tokens and uses unique, sorted,
lowercase ASCII dot-separated IDs. Aliases are complete-value references only.

Canonical files:

- `packages/design-tokens/schema/design-tokens.schema.json`
- `packages/design-tokens/src/token-set.meta.json`
- `packages/design-tokens/src/tokens.source.json`
- `packages/design-tokens/src/contrast-pairs.source.json`
- `packages/design-tokens/src/status-presentations.source.json`
- `packages/design-tokens/src/chart-encodings.source.json`

The repository-owned validator uses only Node 24 standard-library APIs. It
enforces the complete D-083 bounds, UTF-8/LF canonical text rules, closed
fields and types, ordered IDs, DARK/LIGHT parity, structured values, alias
depth and cycles, support-record bounds and a maximum of 200 bounded
diagnostics. It rejects CSS declarations, `url()`, `@import`, control
characters, hostile values and resource overflow before generation.

## 5. Phase 1 bridge and compatibility

The bridge replaces overloaded colour, typography, border, elevation, focus,
motion and layer values with canonical semantic tokens. Safe legacy aliases
remain one-way compatibility aliases. Layout-owned sidebar widths, content
width, responsive padding, breakpoints and component geometry remain local and
outside D1. The legacy `packages/design-tokens/tokens.css` is retained
unchanged as the initial rollback payload; the package export now selects the
generated CSS only after every consumer-switch gate passed.

The bridge did not change markup or interactions. DARK and LIGHT production
captures have no horizontal overflow at 390x844 or 1440x900. Keyboard focus
evidence confirms a 2px ring and 2px offset on every reference route in both
themes.
